## 3. Implementation deviations from `BRIEF.md`

1. T1 general replay is included only after the UltraChat live revision/schema check passes; the candidate is now card-verified as MIT. If inaccessible or inconsistent, replay is omitted and documented.
2. The full T1 total cap is interpreted as 20,000 including replay (not 20,000 cyber rows plus replay). This resolves the brief’s size ambiguity conservatively.
3. The project uses the plain Hugging Face `Trainer` with a custom assistant-mask collator; TRL is not required. Trainer argument names are detected at runtime. This avoids version-sensitive SFT-specific loss masking.
4. A fixed operational throughput budget of three hours and a 20% margin are defaults in `configs/experiment.yaml`; these are planning assumptions, not claims about Colab’s guaranteed session length. The final record count is frozen after the finite pilot and before full training.
5. `requirements-colab.txt` pins the current candidate Transformers/PEFT/bitsandbytes/Datasets/Accelerate/Hub/PyYAML versions checked from PyPI. PyTorch is inherited from Colab to preserve its CUDA-matched wheel. This set has not passed a pilot. The authoring machine reports an RTX 3050 with 6 GiB VRAM, but has no PyTorch/Transformers runtime; the project is not GPU-verified. The preflight must pass in the actual Colab runtime before a full run.
6. Benchmark baseline and trained predictions save row index, answer letters, scoring values, and hashes, but no benchmark question or answer text. The benchmark mirror/original license terms do not clearly authorize text redistribution.
7. Five qualitative outputs are saved; blinded pass/fail rubric counts remain pending manual review. The implementation does not fabricate a rating or use an unregistered evaluator.
8. Loss masks use character offsets from the full rendered tokenization. Since subword tokens cannot be split, a token overlapping one assistant-span edge is supervised whole; a token overlapping multiple assistant spans fails closed.

## 5. Reproducibility, integrity, and safety

- Fixed prompt/system text, model SHA, source revision, benchmark/validation/training hashes, chat-template hash, sequence length, random seed, scoring settings, and library versions participate in fingerprints.
- The model baseline is measured before LoRA/Trainer construction. Each baseline component has an independent fingerprint and is atomically saved.
- The validation set is frozen before baseline and reused unchanged. Baseline/after valid target-token counts are asserted equal.
- Data rows are never concatenated into one whole-corpus string for contamination detection. Records are normalized and visited individually. T1 ingestion is streamed and uses a deterministic reservoir for the bounded candidate mix.
- T1 review samples stay in the local output folder (ignored by Git). Raw datasets, processed rows, model weights, tokens, and training outputs are ignored by Git.
- No benchmark question, split, prompt, checkpoint, or hyperparameter is changed based on benchmark performance.
- No results are pre-generated or represented by placeholder numbers.
